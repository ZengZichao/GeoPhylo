# ADR-1: Ship bundled ICS snapshots as the default data source instead of using pyrolite

- **Status**: Accepted (in force since 0.1.0)
- **Date of record**: 2026-09-11
- **Code**: `geophylo/data/builtin.py`, `geophylo/data/backend.py`,
  `geophylo/data/pyrolite_backend.py`, `tools/build_snapshot.py`,
  `docs/data-policy.md`, `geophylo/data/snapshots/PROVENANCE.md`

## Context

`geophylo` draws the ICS International Chronostratigraphic Chart. Every number
it draws is a scientific claim, and a published figure must be reproducible
years later. That requires a data source that is (a) version-pinned, (b)
verifiable at load time, (c) available offline, and (d) licensed for
redistribution. `pyrolite` already ships a `Timescale` helper and is the obvious
existing implementation in this niche, so it is the main competing option.

The `TimescaleBackend` protocol (`geophylo/data/backend.py`) makes the choice
swappable: the core library depends only on that minimal read-only surface, so
data provenance is an implementation detail rather than an API commitment.

## Decision

Bundle deterministic snapshots of the ICS chart as package data and make them
the default and recommended source.

- Snapshots are generated by `tools/build_snapshot.py` from a pinned upstream
  release (`chart.ttl` at tag `v2026-06.5`, commit `44d1043e…`), whose copy is
  vendored under `tools/source/`. Same input, byte-identical output.
- Each snapshot self-describes: `chart_version`, `source` block, `license`
  block, and `hash.payload_sha256` — a SHA-256 over the canonical JSON of the
  `intervals` array only (sorted keys, compact separators, UTF-8).
- Loading validates: schema, strict age ordering, hierarchy containment, same-rank
  overlap, shared-boundary consistency, colour format, and the payload hash
  against `versions.json`. Any violation raises `DataValidationError`.
- The snapshot directory is append-only; `versions.json` is the only index, and
  an older chart edition is selected with `Timescale(version="2024/12")`.
- `pyrolite` remains available as an **experimental, opt-in, read-only**
  backend (`geophylo[pyrolite]`, version-locked to `>=0.3.7`). It marks every
  capability it cannot verify as `unknown` rather than inventing metadata, and
  its `get_interval()` always raises `IntervalNotFoundError` because pyrolite's
  tables carry no stable identifiers.

## Rejected alternatives

- **`pyrolite` as the required runtime data source.** Rejected: it would make
  every rendered number depend on a third party's data release cadence and
  transcription; it carries no stable IDs, no parent links, no GSSP/GSSA
  definition and no uncertainty fields, which are exactly the states this
  library exposes per boundary. Its fallback-by-name query semantics also differ
  from the strict-rank behaviour the coordinate layer needs.
- **Fetching `chart.ttl` (or the chart PDF) from stratigraphy.org at
  import/render time.** Rejected: network access at render time is not
  reproducible, not offline-usable, and not citable to a fixed version; the
  library performs no automatic network access at all.
- **Re-exporting pyrolite's bundled data tables as "our" snapshots.** Rejected:
  that is second-hand provenance — the upstream attribution and the pinned
  commit would be pyrolite's, not ours, and we could not verify or hash the
  extraction.
- **Shipping only the latest snapshot and documenting "use a newer version for
  older charts".** Rejected: it breaks figure reproduction across chart
  editions, which is the reason `versions.json` and the append-only rule exist.

## Consequences

- The repository redistributes CC-BY-4.0 data, so attribution files
  (`NOTICE`, `LICENSES/CC-BY-4.0.txt`, per-snapshot `license` block) are
  mandatory parts of both the sdist and the wheel, and are checked by
  `tests/packaging/check_wheel.py`.
- Chart updates become a release event: regenerate, run the data-contract and
  visual tests, refresh the sentinel counts in `tests/test_data_contract.py`,
  emit the machine-readable diff, and record the change in `CHANGELOG.md`. A
  scientific data change triggers at least a minor release.
- Snapshot size grows with each appended edition (≈160 KB per edition: the two
  editions shipped at v0.1.0 are 164,843 and 168,544 bytes).
- The derived `2024/12` edition is a reconstruction, not an archived upstream
  release; that limitation is disclosed in `geophylo/data/snapshots/PROVENANCE.md`,
  in `versions.json` (`derived_from`), and in `docs/data-policy.md`.
- Users who genuinely want pyrolite's data get a real, honest path: the
  experimental backend, with its missing capabilities declared as `unknown`.
